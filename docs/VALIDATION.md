# 검증 기록

검증일: 2026-11-11. 대상: Windows x64, Windows PowerShell 5.1, 전용 Node.js 24.22.1, Filee 2.4.0, kordoc 4.24.62, Tesseract 5.4.0.20240606.

## 0.2.0 소스 통합 검증

Filee 2.4.0 소스 1,251개 파일과 kordoc 4.24.62 소스 1,306개 파일을 포함했습니다. 파일별 해시를 확인하고 Filee를 .NET SDK 10.0.403으로 직접 컴파일했습니다. kordoc 소스 모듈 336개는 같은 MCP 프로세스에 번들링했습니다. 설치된 런타임에 원본 `filee-cli.exe`와 npm `kordoc` 패키지가 없음을 검사했습니다.

| --- | --- |

오프라인 복원·실행 검사는 네트워크가 제한된 환경에서 했으며 다운로드나 재빌드가 발생하지 않았습니다. 수신 경로에 .NET SDK·빌드 캐시가 없어도 작성·DOCX 변환·두 OCR 엔진이 동작했습니다. 같은 PC의 별도 절대 경로로 이동한 검사이며 다른 실물 PC 검사는 아닙니다.

복잡한 DOCX 입력은 병합/중첩 표, 그림, 수식, 머리말/꼬리말, 가로 방향 구역을 포함합니다. ZIP 컨테이너의 시간 정보가 아니라 문서 XML·그림 등 각 내부 파일의 실제 바이트를 비교했습니다. 시험 문서에서 통합에 따른 결과 차이가 없다는 뜻이며 모든 문서의 완벽한 변환을 보장하지 않습니다.

필수 실행 환경·엔진·OCR 모델은 **1,500,457,344 bytes (약 1.50 GB)**입니다. 소스를 포함한 오프라인 시험 묶음은 약 **1.55 GB**입니다. 온라인 최초 빌드에 사용하는 SDK·NuGet/npm·다운로드 캐시와 생성 문서는 이 수치에서 제외합니다. GitHub용 소스 ZIP과 MCPB는 각각 약 **24.5 MB**이며, 모델과 실행 환경은 최초 설정 시 준비합니다.

기본 OCR은 `kor+eng+chi_tra`이고 `chi_sim`도 설치합니다. 한국어·영어·한자·숫자 시험을 통과했지만, 혼합 이미지의 짧은 한국어 줄은 오인식했습니다. 그 사실을 결과의 `shortKoreanLineExact: false`로 유지했습니다. 간체자 정확도·모든 수식/필체의 인식률은 측정하지 않았습니다.

[0.2.0 상세 결과](validation-results.json), [소스 통합 구조](SOURCE_BUILD.md). 아래 기록은 이전 버전의 검증입니다.

## 0.1.1 검증 (이전 버전)

한국어·영어·한자용 언어 데이터 4개(`kor`, `eng`, `chi_tra`, `chi_sim`)로 축소했습니다. 기본 OCR은 `kor+eng+chi_tra`이며 숫자를 함께 인식합니다. kordoc OCR·수식 자산 10개는 유지했습니다.

- 별도 0.1.1 런타임을 자동 설치하고, 재실행 시 다운로드 없이 완료 상태로 반환하는 것을 확인했습니다. Windows PowerShell 5.1에서 긴 Node 압축 해제 임시 경로가 실패하는 문제를 수정하고 같은 설치 경로에서 재검증했습니다.
- 전역 Node가 없는 초기 MCP 연결, 25개 도구 연결, 한국어·영어·한자·숫자를 포함한 HWPX 작성·읽기·렌더, Filee 직접 실행과 모든 HWPX 구성 파일 동일성, 기존 출력 보호, 두 OCR 엔진, 제외 언어 거부를 검사했습니다. 통합 검사 9개가 통과했습니다.
- 기본 OCR로 한국어 문장·영어·숫자, 별도 혼합 이미지의 `銀行 金融 漢字`를 인식했습니다. 같은 혼합 이미지의 짧은 한국어 줄 `한글 문서`는 오인식했습니다. 이 실패는 결과 JSON의 `shortKoreanLineExact: false`와 실제 인식 결과에 남겼습니다. 모든 줄이 정확하다는 검사는 아닙니다.
- 자산 14개 SHA-256 검증, ONNX 모델 8개 CPU 로딩을 통과했습니다. Tesseract 텍스트 언어는 4개이고 방향 감지용 `osd`는 유지합니다. 간체자 모델은 설치·해시 검증했으며 실제 인식 정확도는 별도로 측정하지 않았습니다.
- 새 MCPB를 압축 해제하여 최초/설치 완료 MCP 연결과 HWPX 생성을 확인했습니다. 매니페스트·스킬·버전·잠금 의존성 검사를 통과했습니다.
- 새 버전의 필수 실행 환경·엔진·모델은 합계 **1,520,197,929 bytes (약 1.52 GB)**입니다. 이전 언어 목록보다 **189,100,870 bytes (약 189 MB)** 줄었습니다. 다운로드 캐시, 작업 결과, 이전 버전은 별도입니다.

0.1.1에서는 오프라인 내보내기/복원 전체와 실제 Codex/Claude 앱 설치를 재실행하지 않았습니다. 아래 0.1.0 기록은 이전 버전의 검사이며 현재 버전 검사로 대체 표기하지 않았습니다. [0.1.1 결과](validation-results-0.1.1.json), [0.1.0 결과](validation-results-0.1.0.json).

기본 DOCX의 12개, 복잡한 DOCX의 13개 HWPX ZIP 구성 파일이 각각 직접 Filee 실행 결과와 일치했습니다. ZIP 컨테이너의 타임스탬프 대신 문서 XML·그림 등 각 구성 파일의 실제 바이트를 비교했습니다. 복잡한 입력은 병합/중첩 표, 그림, 수식, 머리말/꼬리말, 가로 방향 구역을 포함합니다. 이는 연결 계층이 Filee 결과를 바꾸지 않는다는 검사이며, Filee 자체가 모든 원본 서식을 완벽히 보존한다는 품질 점수는 아닙니다.

## 확인된 한계

- 새 Windows PC 실물이나 사용자의 Claude Desktop UI에 직접 설치하여 검증한 것은 아닙니다. 같은 PC의 독립된 설정·서로 다른 설치 경로·실제 stdio MCP 클라이언트로 검증했습니다.
- 현재 실행 환경에서 Claude 검증기가 일반 디렉터리 두 개를 symlink로 경고했습니다. Windows 파일 속성에서는 일반 디렉터리로 확인했고, 배포 ZIP에는 링크 항목을 넣지 않습니다. 기본 매니페스트 검사는 통과하지만 `--strict`는 이 경고를 실패로 처리합니다.
- Claude CLI의 실제 로컬 마켓플레이스 등록은 이 실행 환경의 파일시스템 검사 및 `fchmod` 오류로 완료하지 못했습니다. Claude 쪽 검증 범위는 공식 매니페스트 검사와 별도 MCPB/stdio 실행 검사입니다. GitHub 원격 저장소 설치 및 앱 UI 설치는 게시 후 해당 클라이언트에서 최종 확인해야 합니다.
- 해당 환경의 junction 생성 기능이 오류를 반환하여 junction 우회 테스트 1개는 명시적으로 건너뛰었습니다. 일반 경로 제한 검사와 실제 경로 해석 코드는 검증했습니다.
- 테스트 이미지 생성 과정에서 폰트 캐시 쓰기 경고가 나왔으나 이미지 생성·한글 렌더링·OCR 검사는 통과했습니다. 글꼴 환경은 PC에 따라 다를 수 있습니다.
- 모든 언어/필체/수식의 인식 정확도를 시험한 것은 아닙니다. 파일 무결성·모델 로딩과 한국어/영어 실제 인식 테스트를 구분했습니다.

샘플 마지막 문장 `테스트 결과를 확인합니다`는 kordoc가 그대로 읽었지만, Filee/Tesseract 결과에는 오인식이 있었습니다. 따라서 “OCR까지 설치된다”는 것을 “OCR이 항상 정확하다”는 뜻으로 안내하지 않습니다.

원격 GitHub 게시, 실제 사용자 클라이언트 설정 변경, 클라우드 계정에 대한 플러그인 설치는 수행하지 않았습니다. 재현 방법은 [개발 문서](DEVELOPMENT.md)에 있습니다.
